PoC Solution Design — where the line sits between a working demo and one that wins

An end-to-end proof-of-concept scope for both Storyboard and Media Room (author → publish → consume), reconciling the client's stated vision against what already runs live on /en. Scope is drawn as three tiers — Minimum (proves the model), Target (the demo the client pictured), Stretch (the differentiators that make it a repeatable VW blueprint). Basis for the upcoming solution-design discussion.

2 · The leverage — what already runs livepublished, pixel-matched at 1440px, on EDS + Document Authoring, built agentically

Start from a running system, not a blank page. The credibility opener for the meeting is a live /en demo. This is why the PoC is framed as gap-closing + assembly, not a build from zero — and why the Minimum tier is essentially already met.
  • Chrome: header + topbar + mega-menu, dark-green footer (7-col sitemap, 4 social, app-store badges), language-switcher shell.
  • Homepage surface: hero, featured promo (index-driven, mobile carousel), Latest Stories + Load-more, 4 auto-populated tag-filtered rails (eMobility / Lifestyle / Škoda World / Latest News), Models + Series rails, social block.
  • Content: 48 story pages imported (flattened) + a live /en/query-index.json (title / date / category / image).
  • Engines: query-index-driven blocks, dedupe/exclude logic, shared memoized index fetch (perf), in-place image optimization (Layout-editability preserved).
  • Reusable machinery: import parsers/transformers, DA source-API push, publish → reindex flow — a pipeline, not a one-off.

4 · The line — Minimum · Target · Stretchthe centerpiece: what must be true at each tier, both sites, with the gating decision and a fallback

Build type: built (live on /en) assembly of built parts net-new Site: SB Storyboard MR Media Room ◆ shared

Minimum proves the model

The PoC counts as a win if only this works: both sites navigable, real content, one complete author→publish→consume loop, the dynamic feature shown happy-path. Almost entirely already met.

  • SB Storyboard homepage + story detail — as-is, rails auto-populating · built
  • MR Media Room homepage — assembled from built rails (featured/news/latest-stories) + lightbox · assembly
  • MR One faceted listing (the shared Media Room listing) over a demo facet subset · assembly · D12
  • ◆ Media-cart happy-path — collect across pages → persistent icon → download a curated set · net-new · D2 · PoC fallback agreed 2026-09-14: if the zip packer isn't ready, download files unpacked (separate)
  • ◆ One live author→publish→consume loop shown end-to-end (edit in DA → publish → appears in a rail) · built
  • ◆ The "not-OOTB" trio narrated (exclude / multi-category / manual+tag) · built

Fallback: if AEM Assets (D5) slips, serve the curated set from the pipeline/CDN — the loop and cart still demo whole.

Target the expected demo

What the client actually pictured — the recommended sign-off line. Bounded, but each item carries a client dependency.

  • SB One Model page + Series (directory → hub) · assembly · SKODA-207/402
  • SB 1–2 full-fidelity stories (in-body galleries + video + Media Box) · assembly · SKODA-604
  • MR Full Images + Videos listing pages — gallery-lightbox + Vimeo embed + per-item cart · assembly+net-new · D2/D5 now M1-blocking
  • MR Media Room model page — 5 tag-driven related strips · assembly
  • ◆ Media-cart with AEM-Assets-served approved set (E3+E4 together) · net-new · D2/D5
  • ◆ EN + CS on homepage + one story + language selector showing only existing locales · assembly · D1 (CS content)

Fallback: CS content late → prove CS structurally (chrome + selector + one page). D2 undecided → client-side happy-path cart for the demo only.

Stretch impresses / wins

The differentiators that turn "a working demo" into "a repeatable VW method." High political payoff, opportunistic.

  • ◆ Figma → AEM agentic generation — 1–2 components, "designed in Figma → generated agentically → live" · net-new · D11
  • ◆ The VW-blueprint narrative (5 min) — reusable pipeline, query-index pattern, agent-handoff candidates · built (narrate) · E7
  • MR Press-kit hub + one chaptered sub-page — TOC + chapter sub-nav + spec table + Media Box · net-new · SKODA-805–808
  • MR Content-embargo showcase — group-restricted + preview-not-live → publish at a time (native EDS; approach agreed 2026-09-14) · net-new · D9
  • ◆ Media Box authoring upgrade — today authors add assets manually; show auto-add-all-by-tag with a delete option as the improvement (client-endorsed 2026-09-14) · net-new
  • MR AI-audio embed on a press release — third-party per-language JS box, retained even though podcast is cut (drop-in, no rebuild) · assembly

Note: nothing here is required for the PoC to succeed — each is a bonus that lands only if its dependency is ready. Deferred to M2 if not: press-kit at scale, embargo, the 5 company/Page types (SKODA-810).

Where the line sits. Minimum is essentially already met — it's assembly + narration of live parts, with a client-side cart fallback. Target is the recommended sign-off scope — it's the demo the client described, and every gap is assembly of built parts, not new invention. Stretch is opportunistic — pursue in parallel, but never let it endanger Target. The build is not the risk; the client-side dependencies below are.

6 · Recommendation — the line to take into the roomwhat to propose the client signs, and the decisions to close in the meeting

Sign the Target tier as the PoC "definition of done", with Minimum as the guaranteed floor and Stretch pursued opportunistically:
  • Guarantee Minimum unconditionally — it's live parts + assembly with a cart fallback; nothing client-side can take it away.
  • Target = the signed scope — end-to-end on both sites (Storyboard: home/story/model/series + full-fidelity; Media Room: home/listings/model + cart with AEM Assets), EN+CS. Every item is assembly of built parts.
  • Stretch = declared bonuses — Figma→AEM, blueprint narrative, press-kit, embargo. Each ships only if its dependency (D11/D9) is ready; none endangers Target.

Close these in the meeting (owner + date each)

  • D5 — is there an AEM Assets instance by build-start? (the #1 threat) · D2 — cart download approach · D1 — CS scope (full vs structural).
  • D12 — the demo-critical facet subset · D11 — which Figma components · D13 — DA vs Universal Editor (architecture-critical).
  • Demo content set owner + the confirmed demo date (the real critical path is content definition, not code).
One-line pitch for the room: "We're already ~60–70% of the way there on a live system. Minimum is essentially done; Target is assembly of parts we've already built; Stretch is where we show this is a repeatable VW method. The only real risk is on your side — so let's name owners and dates for six decisions today."
