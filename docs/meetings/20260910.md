# Project Memory Document
## Škoda Storyboard → Edge Delivery Services (EDS) Migration

**Source:** Re: EDS at Škoda (transcribed meeting)
**Document Type:** Long-term Project Memory / LLM Knowledge Base
**Purpose:** Preserve not only decisions and actions, but assumptions, stakeholder positions, unresolved questions, risks, dependencies, and project context.

---

## 1. Project Definition

### Current Understanding

The objective is believed to be the migration of the existing Storyboard/Media Room platform from WordPress to Edge Delivery Services such that the existing WordPress implementation can eventually be retired. However, this objective has not yet been fully validated against documented requirements, business processes, or stakeholder expectations.

### Important Caveat

A recurring theme throughout the conversation was that the project scope is not fully understood.

Several stakeholders explicitly stated:

- Business analysis is incomplete.
- Requirements are still evolving.
- Governance is not established.
- Security requirements are not finalized.
- Additional functional and non-functional requirements are expected to emerge.

Therefore all current assumptions should be treated as provisional.

---

## 2. Current State Assessment

### What Is Well Understood

The public-facing frontend has already undergone significant analysis by multiple parties.

Adobe has begun evaluating migration patterns and running modernisation tooling against the site.

An initial AI-assisted migration prototype has already produced usable results. Your assessment was that frontend transformation itself should not be a major challenge.

### What Is Not Well Understood

The backend implementation remains poorly understood because:

- Analysts do not yet have WordPress access.
- Existing understanding comes primarily from walkthroughs.
- Some functionality is only known through stakeholder explanations.

Current confidence in backend understanding should therefore be considered moderate to low.

## 5. Technical Assessment

### Frontend Migration

Current confidence: **High.**

Supporting factors:

- AI-assisted migration tools already producing results.
- Initial migrated pages successfully generated.
- Team has prior EDS migration experience.

Current consensus:

Frontend implementation is unlikely to be the primary schedule risk.

### Authoring Model

Current confidence: **Low.**

Outstanding questions:

- Universal Editor?
- Document Authoring?
- Alternative authoring mechanism?

Stakeholders repeatedly identified authoring as a major area requiring further investigation.

Potentially the single biggest unresolved technical design topic.

### Backend Functionality

Known examples include:

**Asset Visibility**

Editors can selectively hide assets despite assets being attached to content.

**Article Categorisation**

Articles may belong to multiple categories.

**Manual Content Recommendations**

Authors can manually promote related content.

**Dynamic Recommendations**

System-generated relationships also exist.

**Restricted Content Areas**

Certain content is protected and used for future product launches.

These behaviours may require custom implementation in EDS.

## 6. Asset Migration Questions

- Some assets are extremely large.
- Storage may involve S3-based repositories.

Open questions:

- Should assets migrate into AEM DAM?
- Is DAM migration in scope?
